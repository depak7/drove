Drove runs on your laptop, using the coding CLIs you're already paying for. Claude, Codex, opencode. There's no API key to paste and no account to make. If you can run claude in a terminal today, you can run this.

The model that wrote the code doesn't get to mark it

This is the part I'd argue about. Ask one model to check its own work and it'll usually tell you the work is fine — not because it's lying, but because it already believes the reasoning that produced it. So Drove hands the diff to a completely different model, in a fresh session, with none of the first one's thinking attached. Claude writes, Codex marks. Flip it round if you prefer. The same bug found twice by two models that never spoke is worth something.

It never touches the code you're editing

Every feature gets its own git worktree. Your actual checkout sits there untouched, and you can keep working while a run is going. (This started as a safety thing. It turned out to be the reason you can have four features running at once without them stepping on each other.)

One change, two repos

Rename something in your API and fix every caller in your web app, in one go, on a branch with the same name in both. Most tools make you do this twice and hope you remembered everything.

You get a write-up, not a thumbs up

What you asked for, what changed, what the reviewer said each round, your test output, what it cost. And if the same model ended up writing and reviewing — say you've only got one CLI installed — it says so instead of quietly letting you assume otherwise.

You can get your hands in

Read the diff file by file. Browse the whole thing. Or open a terminal right there in the worktree and run the tests yourself, because sometimes that's just faster than reading.

What it's actually good at

The jobs where you already know what "done" looks like and you just don't want to spend the afternoon typing it.

Renames that span repos

The kind you keep putting off because it's twenty files in two places.

A second model reads them, so you don't get fifty tests that assert nothing.

It runs your test suite before it'll call the job done.

Paste the trace. The plan comes back naming real files, not guesses.

The frontend bug tests can't see

Turn on browser checks and it opens the page after the run. One component throwing on render, build green, page blank — that one.

Five at once

It waits for you at the plan, then gets on with it. Queue a few before coffee, approve the plans, come back to branches.

Two commands and you're going

Run it from wherever. It's one thing running on your machine, not something you install per project — you point it at repos rather than running it inside them.

Where it falls down

You'd find all of this out in a week anyway. Better you hear it now.

It can't tell you what to build

It writes a plan. You approve it. If the plan looks fine and it's actually wrong, you'll get exactly the wrong thing — reviewed, tested, delivered on a tidy branch with a confident write-up. The review catches bad code. It doesn't catch a bad idea.

Two repos means two merges

The branches share a name. Git doesn't care about that. You merge them yourself, and if you land one and forget the other you've broken the build. Drove warns you in about three places. It can't actually stop you.

It gives up after two rounds

If the reviewer keeps blocking and the builder keeps disagreeing, it stops and asks you. I'd rather that than a third model casting a tie-break vote it can't really justify. Plenty of people will disagree — that stage is designed and sitting in the TODO.

The Mac app isn't signed

So it installs from source, which means you need a terminal. I'm not going to tell you to strip the quarantine flag off an app that can write to your repos. It's a $99 problem rather than a code problem, and it'll get fixed when someone who isn't me wants to run it.

It spends your money

Real tokens on your own subscription. Building this thing, the small jobs came in around twenty or thirty cents and the meaty ones a dollar or two. Every run records what it cost, so you can decide whether it was worth it rather than guess.

It's new

It builds itself now — the Stop button, the landed-branch detection and half the diff viewer were written by Drove, reviewed by a model that didn't write them. That's a decent smoke test. It's still version 0.1 by one person, so read the code before you hand it anything that matters.
